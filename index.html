01

先搞懂：GitHub 到底是什么

在动手之前，先用生活里的类比建立概念，后面所有操作都会变得好理解。

一句话解释

GitHub 是一个把代码（或任何文本文件）放在云端、可以记录每一次改动、并方便多人协作的网站。你可以把它理解成「带历史版本记录的云盘 + 协作空间」。

它本身建立在 Git 这个版本控制工具之上：Git 负责记录改动，GitHub 负责把这些记录放到网上、供人查看和协作。

用一个类比记住它

  • 仓库（Repository）：就像一个项目文件夹，里面装着这个项目的全部文件。
  • 提交（Commit）：像给文件夹拍了一张「存档快照」，写清这次改了什么。
  • 分支（Branch）：在不影响主线的前提下，另开一条副本去试验新想法。
  • Pull Request：把你改动好的内容「申请合并回主线」，请别人检查。

存文件与历史版本

每次修改都会留档，改错了可以翻回任意一次历史版本，不怕覆盖丢失。

多人协作

同事各自在自己的分支上修改，再通过评审合并到一起，改动过程清晰可追溯。

公开分享与学习

大量开源项目公开在上面，可以浏览别人的代码、提建议，也可以展示自己的作品。

02

注册账号并登录

第一步先拥有自己的 GitHub 账号。整个过程只需要邮箱、密码和一个用户名。

github.com/signup
示意注册页依次填写用户名、邮箱，设置密码后提交；GitHub 会发送验证邮件，按提示完成验证即可。
  1. 打开官网注册
    浏览器访问 github.com，点击 Sign up，输入邮箱并设置密码。
  2. 起一个用户名
    用户名会出现在你的仓库地址里（github.com/用户名），建议用好记、规范的英文或拼音，后续改名也可以，但尽量一次定好。
  3. 完成邮箱验证
    去邮箱收验证邮件并点击链接；未验证会影响部分功能，建议注册当天就完成。
  4. 登录与完善资料
    回到 github.com 点 Sign in 登录；右上角头像进入个人主页，可补充昵称、头像和简介。

新手提醒

用户名属于公开信息，不要在里面写手机号、身份证号等隐私内容。密码请使用独立、足够复杂的一串，不要与其他网站重复。

03

创建你的第一个仓库

仓库（Repository，常简称 repo）是存放项目文件的地方。新建仓库是把项目放上 GitHub 的起点。

  1. 点击新建仓库入口
    登录后，点右上角头像旁边的 + 号，选择 New repository；也可以在首页左侧直接看到该入口。
  2. 填写仓库名称
    Repository name 填一个项目名，比如 hello-world。名字用英文、数字和短横线，不要带空格。
  3. 选择公开或私有
    Public（公开）：任何人都能看到；Private（私有）：只有你和被邀请的人能看到。练习阶段可选 Public。
  4. 初始化仓库
    勾选 Add a README file，让仓库自动带上一个说明文件，创建后不会是空仓库，方便下一步操作。
github.com/new
示意① 填仓库名；② 选 Public / Private；③ 勾选 README 初始化。填写完成后点底部绿色按钮创建。

README 是什么

README 是仓库里的「门面说明文件」，通常用 Markdown 写法，介绍项目是做什么的、怎么使用。别人点开你的仓库，第一眼看到的往往就是它。

04

上传与编辑文件

不需要安装任何软件，直接在网页上就能新建、上传和编辑文件。下面以编辑 README 为例。

github.com/your-name/hello-world
示意① 仓库主页列出所有文件；② 点开文件后用右上角铅笔图标进入在线编辑，改完下拉到页面底部提交。
  1. 进入要改的文件
    在仓库主页点击文件名打开，再点右上角的铅笔（Edit）图标进入编辑模式。
  2. 直接在网页上修改
    左侧编辑文字，右侧可预览 Markdown 渲染后的效果。README 常用标题、列表、链接等写法。
  3. 上传已有文件
    在仓库主页点 Add file → Upload files，把本地文件拖进虚线区域，等待上传完成。
  4. 填写改动说明并提交
    改完后拉到页面底部，在「提交更改」框里写清这次改了什么，再点绿色按钮保存（下一节详解）。

网页操作 vs 本地 Git

网页端适合改少量文本、上传小文件；当项目变大、需要频繁同步时，才需要安装本地 Git 工具并通过命令行推送，入门阶段用网页端完全足够。

05

提交记录与分支

每一次保存改动都叫一次提交（Commit），它是 GitHub 记录历史版本的基本单位；分支则让你能平行地开发不同功能。

提交更改 · 在线编辑底部
示意① 第一行写本次改动的简短标题；② 选择提交到哪个分支，新手先直接提交到 main。

main 分支

仓库默认的主线分支，通常存放可以正常使用的版本。最初所有提交都在 main 上。

新建分支

点仓库上方的分支下拉框，输入分支名即可开一条副本。在新分支上改动不会影响 main。

查看历史

点仓库的 Commits 可以看到每次提交的标题、时间和作者，点开能对比具体改了哪些内容。

好的提交信息怎么写

标题用一句话说清「做了什么」，例如 修复登录按钮错位、新增使用说明章节；避免写成「更新一下」「改了点东西」这类事后无法追溯的描述。

06

发起 Pull Request 协作

Pull Request（简称 PR）是 GitHub 协作的核心：你在分支上改完后，申请把改动合并回主线，并邀请别人查看、讨论和确认。

Pull Request 讨论页
示意① 绿色「可合并」表示无冲突、可以合并；② 确认无误后点合并按钮，分支内容进入 main。
  1. 在分支上完成改动并提交
    先确保自己的改动都已提交到功能分支上。
  2. 发起 New Pull Request
    进入仓库的 Pull requests 标签页，点 New pull request，选择「从哪个分支合并到 main」。
  3. 写清标题和说明
    说明这次改动解决了什么问题、改了哪些文件，方便评审人快速理解。
  4. 等待评审与合并
    协作者可以在下面留言讨论；确认没问题后由有权限的人点 Merge pull request 合并，PR 流程即完成。

什么是冲突

如果两个人同时改了同一处内容，合并时 GitHub 会提示冲突（conflict），需要手动决定保留哪一版后才能合并。这是协作中的正常现象，不必紧张。

07

把 HTML 文件部署成公开网页

仓库里的 HTML 默认只是「文件」，别人点开看到的是源码。借助 GitHub 自带的 GitHub Pages 功能，可以把仓库里的网页直接发布成一个可访问的网址，免费、无需服务器。

先理解：Pages 是怎么回事

GitHub 会把你仓库里指定分支上的文件，当成一个静态网站托管起来。配置完成后，访问形如 https://用户名.github.io/仓库名/ 的地址，就能看到你的页面。改完文件重新提交后，等待片刻网页会自动更新。

仓库 → Settings → Pages
示意① 在 Branch 下拉选择 main 分支、根目录并保存；② 发布成功后这里会出现可访问的网站地址。
  1. 把 HTML 上传到仓库
    按第 04 章的方法，把网页文件传到仓库。首页文件必须命名为 index.html，Pages 会默认把它作为网站首页。
  2. 打开仓库设置
    进入仓库主页，点顶部的 Settings（设置）；在左侧菜单找到 Pages 选项。
  3. 选择发布分支并保存
    在 Branch 处选择 main 分支、目录保持 / (root)，点 Save。
  4. 等待生效并访问网址
    等待 1～3 分钟，回到此页面，绿色提示区会显示你的网站地址，点开即可在浏览器看到发布后的页面。

文件路径要对应好

如果 index.html 放在仓库根目录，网址直接打开首页；如果放在 docs/ 子目录，需在 Pages 设置里把目录选为 /docs。页面里引用的图片、CSS 等资源也要用相对路径，否则上线后会裂图。

常见问题对照

  • 打开是 404 页面：刚保存需等待几分钟；也可能是首页没叫 index.html，或文件所在目录与 Pages 设置不一致。
  • 改了文件网页没变化：确认改动已提交到所选分支；Pages 有缓存，可等一会儿或强刷页面（Ctrl / Cmd + Shift + R）。
  • 页面样式/图片丢失：多为资源用了本地绝对路径，改成 ./图片名.png 这类相对路径后重新提交。
  • 私有仓库能用 Pages 吗：免费账号下 Pages 通常仅对公开仓库开放；私有仓库的 Pages 属于付费功能，按页面提示为准。

HR 资料上传合规红线速查

作为 HR，日常接触简历、档案、薪酬绩效等敏感资料，上传或外发前必须先判断能不能对外。下面这张对照表用于快速自检；完整规定见配套的《HR 数据与资料上传合规红线须知》。

三条兜底原则

  • 最小必要，按需可见：HR 数据只在公司授权系统、给确有需要的人使用，外部平台不是存放简历和档案的地方。
  • 公开即不可逆：链接外发或上传外部空间后，即使马上删除，也可能已被转发、下载、截图或缓存。
  • 存疑先问：判断不清能不能给外部时，先停下问 HR 负责人 / 安全 / 法务，不要先传了再说。

发布前快速自检

外发前确认：无真实个人信息、无薪酬绩效与档案隐私、不是可识别到个人的汇总表；文件存放在公司指定系统，共享链接按人授权并设有效期，示例一律用虚拟数据。若不慎误传，立即停止分享并上报 HR 负责人与信息安全团队，不要自行删除了事。

09

Star、关注与探索项目

学会逛别人的仓库，是 GitHub 学习的重要一环。下面几个按钮是你浏览项目时最常用到的。

某个开源仓库主页 · 右上角按钮区
示意Star 收藏项目、Watch 接收动态、Fork 把别人的仓库复制一份到自己账号下再改动。

Star 收藏

看到有用的项目点 Star，相当于加入书签；个人主页的 Stars 列表就是你的收藏夹，方便以后找回。

Watch 关注动态

关注后，该仓库的 Issue、PR、发布等更新会通知到你的通知中心，适合你深度参与的项目。

Fork 复刻仓库

想在别人项目基础上改，先 Fork 一份到自己账号，再从自己的副本提 PR 回原项目，这是开源贡献的常见方式。

10

常见名词速查

学到后面遇到不熟的词，可以回到这张表快速对照。

Repository / Repo
仓库，存放项目全部文件和历史版本的地方，对应 GitHub 上的一个项目主页。
Commit
一次提交，对文件改动的一次存档快照，附带说明标题、时间和作者。
Branch
分支，从主线分出的平行副本，用于开发新功能或试验，互不干扰。
main / master
仓库默认主线分支名；新项目多为 main，老项目可能叫 master，作用相同。
Pull Request / PR
合并请求，申请把某分支的改动合并到另一分支，并附带评审与讨论流程。
Issue
议题，用来记录 bug、需求、讨论事项，可指派人员、打标签和关联 PR。
Fork
把他人公开仓库复制一份到自己账号下，便于独立修改后再贡献回去。
README
仓库说明文件，通常介绍项目用途、使用方法和贡献方式，常用 Markdown 编写。
Merge
合并，把一个分支的改动并入另一个分支；PR 评审通过后执行的动作。
Conflict 冲突
合并时同一处内容被多方修改导致无法自动合并，需人工取舍后再提交。
GitHub Pages
GitHub 免费提供的静态网页托管服务，可把仓库里的 HTML 直接发布成公开网址。
index.html
网站首页默认文件名；部署网页时根目录下的首页必须叫这个名字，否则访问网址会 404。

下一步可以练什么

注册并建好第一个仓库后，建议按顺序练习：编辑一次 README 并写好提交信息 → 新建一条分支改点内容 → 发起一个 PR 并合并 → 上传一个 index.html 并用 Pages 发布成网页 → 找一个感兴趣的开源项目点 Star 或 Fork。跑通这一轮，就完成了 GitHub 入门。
